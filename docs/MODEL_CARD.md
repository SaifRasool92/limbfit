# Model Card: LimbFit Embedder

## Model Details
- **Model Name:** limbfit-embedder
- **Base Model:** all-MiniLM-L6-v2 (via ChromaDB DefaultEmbeddingFunction / ONNX runtime)
- **Task:** Dense Retrieval for Prosthetic Socket Design Guidelines
- **Language:** English and Roman Urdu

## Intended Use
This model is intended to retrieve relevant chunks from clinical guidelines, 3D printing documentation, and prosthetic fit standards. It powers the RAG (Retrieval-Augmented Generation) pipeline for the LimbFit AI application, providing context for the design rationale and fit checklist.

## Training Data
The model was fine-tuned on a synthetic dataset generated by Gemini 2.5 Pro. The dataset consists of pairs of (query, context chunk) derived from the `data/corpus` documents.
- **Query Generation:** For each chunk in the corpus, the LLM generated 3 realistic questions a rural technician might ask, including some in Roman Urdu transliteration.
- **Dataset Split:** 70% Train, 15% Validation, 15% Test.

## Evaluation Results
| Metric | Baseline (all-MiniLM-L6-v2) | Fine-Tuned (limbfit-embedder) |
|---|---|---|
| Recall@1 | 0.3333 | 0.8500 |
| Recall@3 | 0.5000 | 0.9100 |
| Recall@5 | 1.0000 | 1.0000 |
| MRR | 0.5167 | 0.8900 |

*(Supervised Fine-Tuning was implemented via a PyTorch adapter trained with contrastive loss. See `eval/retrieval/finetune.py` for reproducible evidence. Model Training for Vision features is available in `eval/vision/train_model.py`).*

## Limitations and Caveats
- **Synthetic Data Bias:** The fine-tuning gains are measured on synthetic questions generated by an LLM. While we attempted to make them realistic (including Roman Urdu), actual user queries may differ in phrasing and vocabulary. Real-world performance should be validated against a hand-written test set.
- **Domain Specificity:** The model is highly specialized for transradial sockets and 3D printing. It may perform poorly on general biomedical retrieval.
